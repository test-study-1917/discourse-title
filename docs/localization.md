# 为论坛增加插件翻译

插件跟随 Discourse 当前界面语言，使用原生翻译加载与英文回退。现有翻译覆盖当前本地 Discourse 的 49 个语言／地区代码；完整清单以 `config/locales/client.*.yml` 为准。语言列表不写在组件中，也没有限制论坛新增语言的白名单。

## 新增一种语言只需要两份文件

先确认目标语言已经是论坛可用的界面语言；插件翻译文件不会为 Discourse 注册新的界面语言。

以论坛新增的 `fr_CA` 为例：

1. 从英文文件复制结构，新增 `config/locales/client.fr_CA.yml` 和 `config/locales/server.fr_CA.yml`。若已有文件，直接更新原文件。
2. 将两份文件最外层的 `en:` 改为 `fr_CA:`，保持文件名、根节点和论坛语言代码一致。
3. 翻译所有文案。`client` 文件包含目录界面和后台分类名称，`server` 文件包含站点设置说明。
4. 保留 `%{count}` 等占位符及表示标题标记的 `#`，不将它们翻译或替换成全角符号。
5. 按目标语言补齐 `count` 的复数形式，执行下文检查，然后将文件随插件同步到部署环境并重载服务。

无需修改 JavaScript、设置项或语言注册表。若目标语言没有翻译文件，或某个键缺失，Discourse 会回退到英文；新增界面语言不会自动生成翻译。

## 数量按目标语言的复数规则翻译

不要只把英文的 `one` 和 `other` 原样套到所有语言。阿拉伯语使用 `zero / one / two / few / many / other`，俄语使用 `one / few / many / other`，日语只需要 `other`。

例如，俄语目录数量为：

```yaml
ru:
  js:
    reply_titles:
      count:
        one: "%{count} ответ"
        few: "%{count} ответа"
        many: "%{count} ответов"
        other: "%{count} ответа"
```

这只是数量部分的示例；完整文件还应保留英文模板中的其他文案。

## 检查文件与目标论坛的语言覆盖

```sh
npm run check:locales
```

检查会自动发现翻译文件，验证前后台文件配对、翻译键完整、文案非空、占位符一致，以及各语言需要的复数形式；不需要另加测试语言清单。

如需核对目标 Discourse 版本是否新增了语言，指定其源码目录：

```sh
DISCOURSE_ROOT=../discourse npm run check:locales
```

此时还会检查目标论坛的所有 `client.*.yml` 语言是否已在插件中提供翻译。没有 Discourse 源码时，普通检查仍可独立运行。

最后在论坛中切换界面语言、保存并刷新主题页，检查目录标题、数量、按钮、提示及后台设置；从右向左书写的语言还应检查窄屏和目录展开状态。
